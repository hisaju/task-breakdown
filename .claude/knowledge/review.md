# レビューの知見

- フォーカスリング・枠線など「状態を示す色」は白地・canvas 地でコントラスト 3:1 以上のトークンを使う。`brand-soft` は約 1.1:1 で見えない（#12, 2026-10-25）
- 完了状態などの UI 状態は `data-*` 属性を唯一の源にし、Stimulus が `classList.toggle` で独自に状態を持たない。初期描画で属性・見た目・`aria-label` を一致させる（#12 の申し送り, 2026-10-25）
- 子タスク間で前提にする `data-*` 属性は、使う側だけでなく「付与する側」の AC にも明記する（S-5 親行の `data-done` が漏れかけた）（#12, 2026-10-25）
- 空状態は「なぜ 0 件か」（完了フィルタ／日付タブ／データ無し）ごとに文言とターゲットを分ける。共通 controller の empty を 1 つにすると、別理由の 0 件で誤った文言が出る（#13, 2026-10-25）
- 同じ部品（`_menu` 等）を一覧で繰り返すときは、トリガーの `aria-label` に対象名を入れ、`id` を行ごとに一意に生成する（#13, 2026-10-25）
- 時間で動く UI（自動遷移等）の system spec は待ち時間に頼らず、`data-*-value` で遅延を短く上書きして検証する（#14, 2026-10-25）
- 1 子の差分が 500 行を超えたら同じ Issue のまま前半／後半の PR に分け、前半は `Refs #n`、後半で `Closes #n` にする（#14, 2026-10-25）

- 一覧の行ごとの読み上げ名（完了チェック・メニューの `aria-label`）は、その場で名前を入力できる行では入力に追随させる。入力前の既定名（「新しいタスク」）も決めておく（#8, 2026-10-25）
